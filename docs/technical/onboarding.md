# Онбординг по tui-onboarding-placeholders.fig

Источник: пересобранный владельцем `tui-onboarding-placeholders.fig`, 3 798 083 байта. Прочитан сам бинарный canvas: fig-kiwi v106, схема Kiwi и Zstandard-данные, 70 721 узел с импортированными библиотеками. Компактная [выдержка](../../design-system/onboarding-placeholders.json) содержит SHA-256 исходника и выбранные мастера без редакторских/пользовательских метаданных. Она дополняет прежнюю JSON-выгрузку и имеет приоритет для компоновки онбординга.

Файл содержит страницу «Примеры», а не отдельную страницу с текстовыми правилами. Для МАЙТИМ выбран Image Centered:

- iOS `17364:18348`, 375×812: illustration 220×220, image/content — по половине контейнера, внутренний отступ иллюстрации 24; large header с padding 16, gap 16 и bottom 24; AppBar 56 с прогрессом и возвратом.
- Android `17364:18364`, 360×800: та же композиция, illustration 220×220, AppBar 56.
- Нижний action-container (`17364:18243` и `17364:18246`): боковые отступы 16, кнопка 56, нижний отступ 24 плюс системная безопасная область.
- iPad `16785:24729` помечен legacy: центральный контейнер 540 с иллюстрацией и кнопкой. Отдельного актуального desktop-мастера в этой странице нет. Для широкого веба использована центральная поверхность шириной 540 и адаптивной высотой 680–760; это наша адаптация примера iPad, не выдуманная desktop-спецификация.

Вместо прежней вложенной карточки: белая поверхность, сверху центральная декоративная иллюстрация, затем заголовок и описание с выравниванием влево, отдельно нижняя основная кнопка. На телефоне поверхность занимает весь экран. Прогресс перенесён в AppBar, на шагах 2/3 есть «Предыдущий шаг». В тексте для экранного диктора и aria-valuetext указан текущий шаг. Фокус после перехода получает заголовок.

Примеры банковских текстов и системные status/home bars не переносятся в приложение. Банковская иллюстрация phone-check заменена существующей иллюстрацией МАЙТИМ «М/Ы» в области 220×220. Пропорции адаптированы к реальному viewport: высота image 42svh с ограничениями, а на низких окнах 220. На обычном размере flex-компоновка держит основную кнопку внизу; при нехватке высоты страница с кнопкой прокручивается целиком, без перекрытия текста. Safe-area применяется к отступам.

Продуктовые ограничения сохраняются: три шага без «Пропустить», гостевое открытие/выход начинают первый шаг, введение не вызывает API, только последняя явная кнопка начинает Telegram-вход. Обязательный профиль остаётся после входа и до доступа к приложению. История, профиль, оценка, API и недельный цикл не меняются.

Проверка: `scripts/qa/design-browser.cjs` (запуск описан в [design.md](design.md)). Дополнительно к полному UI-флоу проверяются 1→2→1, перезапуск на первом шаге после reload, прогресс 1/2/3, отсутствие skip, короткое окно 568 px, отсутствие перекрытия текста кнопкой и горизонтального переполнения. Все запросы перехватываются локальными JSON-фикстурами, реальных Telegram-доставок нет. Размеры 1440/393/390/320, мобильные платформы эмулируются в Chromium; физические устройства и Safari не проверены.
