# Именованные события расписания

GitHub cron выбирает событие явно в `scripts/run_schedule.py`:

| Cron UTC | МСК | Event |
|---|---|---|
| 0 6 * * 2 | Вторник 09:00 | feedback |
| 0 18 * * 2 | Вторник 21:00 | prepare |
| 0 6 * * 3 | Среда 09:00 | publish |
| 30 6 * * 3 | Среда 09:30 | publish — резервный повтор |
| 5 12 * * 3 | Среда 15:05 | publish — дополнительное восстановление публикации |
| 0 6 * * 4 | Четверг 09:00 | invite |

`POST /internal/schedule/`: `{"mode":"run","event":"publish","round_date":"2026-10-28"}`. round_date необязательна, означает дату среды раунда, не подменяет часы. Без event запуск run отвергается. Неизвестные события, лишние параметры, даты не среды и clock overrides запрещены. OIDC-проверка exact main workflow, repository/ref и запрет browser Origin сохранены. `{"mode":"verify"}` только проверяет доступ и БД.

Сервер определяет наиболее поздний раунд, для которого наступил срок выбранного события. Runner закрепляет возвращённую round_date для всех повторов одного запуска, не переключаясь на другой раунд. Для ручного восстановления можно указать среду явно; этот запуск всё равно проверяет серверное время, состояние и ранее выполненные действия.

Окна (Europe/Moscow): prepare — вторник 21:00 до следующего вторника 21:00; publish — среда 09:00 до следующего вторника 21:00; feedback — вторник 09:00 до среды 09:00; invite — четверг 09:00 до закрытия записи во вторник 21:00 (для явного ручного восстановления). Правые границы исключены. Вне окна prepare/feedback/invite пропускаются. Поздний publish не запускает устаревшую активность: он фиксирует отмену и уведомляет записавшихся, пока неделя ещё актуальна. Пауза публикации сохраняется. Существующие профили, состав, ручные правки и достижения не мигрируют.

Publish восстанавливает пропущенную подготовку только для того же раунда: пустой состав строится автоматически, полностью валидный ручной состав без отметки готовности принимается без изменений. Частичный/ошибочный состав не перезаписывается: активность отменяется, данные сохраняются. Prepare не публикует, не запрашивает оценку и не приглашает. Приглашение не догоняет запрос ОС. Ручная пауза публикации всегда приоритетна, включая проверку после окончания пользовательской недели. Системная пауза placeholder отличается от ручной: при готовом адаптере снимается автоматически, при неготовом активность отменяется в publish.

Выбор этапа и его очередь ограничены event + round. Отчёт доставки рассчитывается только при publish. Ошибки и уведомления о них также имеют scope события/раунда; чужая ошибка не отравляет результат. Обработка просроченных sending leases также ограничена выбранной очередью; uncertain/unknown не переотправляются автоматически. Идемпотентность прежних Job/Notification ключей сохранена при переключении схемы.

Служебное обновление completed/expired у истекших раундов выполняется внутри допустимого запуска без распределения или рассылок. Оно не удаляет историю. Старый jobs.tick остаётся локальным помощником совместимости для существующих тестовых фикстур; ни endpoint Actions, ни management command tick его не вызывают.

Безопасная проверка на production: workflow_dispatch event=verify. Для реального восстановления выбрать нужное событие и round_date; оно может отправлять реальные сообщения. Тесты используют только локальную БД, изолированных участников и подменённый Telegram transport. При выкладке сервер нового контракта обновляется перед переключением workflow; production-тесты рассылки не запускаются.


Подробные правила выбора и аудита: [weekly-lifecycle.md](weekly-lifecycle.md).

## Задержки Actions 4 ноября 2026

Подготовка раунда 04.11 успешно завершилась 4 ноября около 02:14 МСК. Основной publish 09:07 был запущен GitHub только в 17:19 МСК (задержка 8 часов 12 минут); прежняя граница 15:00 привела к отмене уже подготовленной активности. Успешный workflow означает обработанную отмену, а не состоявшуюся публикацию.

Теперь prepare и publish разрешены до окончания пользовательской недели — следующего вторника 21:00 МСК (Round.ends_at − 12 часов). Восемь часов задержки и запуск на следующий день не отменяют активность. Уже подготовленный состав и организатор сохраняются; повторы не дублируют сообщения. Пропущенная подготовка восстанавливается прежним механизмом. Ручная пауза остаётся приоритетной, ранее отменённые раунды автоматически не возобновляются. Нет подмены часов, переименования активности или сдвига календаря.

После границы публикация запрещена как через endpoint, так и напрямую через jobs.publish; устаревшие назначения не доставляются. При отмене из-за пропуска срока текст сообщает, что активность не удалось запустить вовремя, вместо неверного объяснения о подготовке. Существующие записи, история и правила обратной связи сохраняются; миграций нет.
