# Задержки API — 25 октября 2026

Причины: исходный API в Render Ohio, БД Supabase в Paris (eu-west-3); последовательные SQL-запросы проходили через Атлантику. Дополнительно middleware делал exists(session_key), затем Django ещё раз загружал ту же сессию. Сохранение неизменённой команды повторно читало команды и открывало отдельную транзакцию.

Исправления:
- бесплатный Render Frankfurt, тот же Supabase и SECRET_KEY сессий;
- 1 загрузка сессии вместо exists + load, без ослабления проверки истечения;
- 3 SQL на повторный GET профиля/истории;
- 4 SQL на сохранение имени/города с той же командой: сессия, пользователь, UPDATE, достижения;
- пересчёт команды и транзакция только если команда изменилась/ещё не нормализована;
- соединения с БД живут до 600 секунд вместо 60;
- безопасный Server-Timing для диагностики, без записи SQL и параметров.

## Измерение на реальном API

HTTP-запросы к /health/ready: SELECT 1 и чтение существования профилей, без записей и имитации пользователей. Старый и новый сервисы измерялись с одного cloud-клиента параллельно. Это небольшая выборка, не нагрузочный тест и не замер браузера пользователя.

| Сервис | Регион | Три полных ответа, мс |
|---|---|---|
| Прежний API | Ohio | 961, 962, 652 |
| Новый API | Frankfurt | 312, 306, 227 |

У нового API суммарное SQL-время этих двух запросов: 20.8, 19.8, 21.4 мс. Полное время внутри приложения: 98.1, 89.2, 22.3 мс (первые соединения с БД дополнительно инициализировались). Разница между временем приложения и HTTP включает сеть/прокси/TLS; одинаковая задержка у каждого пользователя не гарантируется.

Операции реального пользователя и отправка Telegram не использовались для теста. Бюджеты SQL, сохранность авторизации/CSRF и истечение сессии проверены в изолированном PostgreSQL. Старый Ohio адрес временно доступен открытым вкладкам, чтобы переключение не оборвало работу; после обновления страницы клиент использует EU и прежнюю серверную сессию.

Free Render может засыпать после простоя. Регион и оптимизация SQL ускоряют прогретые запросы, но не устраняют первый холодный старт бесплатного сервиса. Фоновый keepalive и дополнительные периодические рассылки не добавлены.
