# Уведомления о действиях

Источник — прочитанный `tui-notification-toast.fig` (Kiwi + Zstandard, 51 203 узла с импортированными библиотеками). Выбранные мастера, SHA-256 и основные правила сохранены в [notification-toast.json](../../design-system/notification-toast.json). Реализация: `web/toasts.js`, `web/toasts.css`.

Тост сверху, короткий текст, автоисчезновение через5с; доступная кнопка закрытия и свайп вверх. На телефоне — очередь по одному, на desktop — стопка, новый тост сдвигает предыдущие вниз. Визуально применены white/base, семантические success/error иконки24, mobile min-height48/radius24, desktop min-height56/radius16, desktop max-width текста400; внутренние отступы12, gap8. Отступ сверху для web —48px iOS,36px Android, плюс safe-area. Кнопка закрытия имеет область44px; это веб-адаптация источника. Текст не обрезается при увеличении шрифта. Hover/focus приостанавливают таймаут. Фокус автоматически не забирается, announcement polite, reduced-motion отключает анимацию.

| Действие | Успех | Ошибка |
| --- | --- | --- |
| Запись | Ты записан на активность | Не удалось записаться. Попробуй ещё раз |
| Отмена | Запись отменена | Не удалось отменить запись. Попробуй ещё раз |
| Оценка | Оценка отправлена | Не удалось отправить оценку. Попробуй ещё раз |
| Первый профиль | Профиль создан | Не удалось сохранить профиль. Попробуй ещё раз |
| Обновление профиля | Профиль обновлён | Не удалось сохранить профиль. Попробуй ещё раз |

Для закрытой записи отдельное сообщение; ошибки валидации дают «Проверь заполненные поля» и сохраняют сообщения непосредственно у полей. Нативная проверка обязательных полей тоже вызывает тост. Общие action-плашки и кнопки retry внутри формы удалены; повторная отправка — основной кнопкой, ввод сохраняется. Ошибки загрузки экранов с retry продолжают показываться на самом экране.

Успех появляется только после успешного POST с ожидаемым состоянием API. Ошибка последующего GET не превращает уже сохранённое действие в неуспех: подтверждение POST и ошибка загрузки — разные состояния. Повторные клики во время отправки блокируются. Logout очищает очередь; отменённые ответы старой авторизации не порождают уведомления.

Для оценки используется popover/manual в верхнем слое и внутри открытого dialog. После закрытия dialog host переносится в body, сохраняя активные тосты и таймеры. Это позволяет показать ошибку в диалоге и сохранить успешное подтверждение после возврата к истории/активностям. Если Popover API недоступен — fixed-host без popover. Проверка визуального top-layer/announcement остаётся частью финального браузерного прогона.

По действующему указанию владельца выполнены только `node --check` для изменённых JS и `git diff --check`. Полный прогон и скриншоты сейчас не выполнялись. В UI regression обновлены старый текст подтверждения профиля и фикстура POST-ответа оценки; сам regression не запускался. На финальном тестировании нужны success/error для всех действий, валидация, сохранение ввода, очередь/таймаут/закрытие, переход из диалога, отсутствие дублей после logout и мобильная доступность.
