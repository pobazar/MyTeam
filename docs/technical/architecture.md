# Архитектура

Один модульный Django-сервис: серверный рендеринг уменьшает клиентскую поверхность секретов, ORM даёт транзакции и версионируемые миграции. PostgreSQL — источник истины. SQLite предназначена только для локальной разработки. Ни микросервисов, ни универсального конструктора форматов.

Границы: users — идентичность/профиль; rounds — запись и сроки; activities — правила формата и инструкции; matching — распределение; notifications — outbox и доставка; jobs — устойчивые этапы; feedback — ответы и ачивки; monitoring — инциденты; analytics — история событий. Модели общие в models.py для явных ограничений и связей.

Activity имеет стабильный key, version, title, инструкции, build_groups, valid_distribution, фабрику feedback_form, шаблон карточки и achievement_key; конкретный подбор находится в activities/coffee.py. Снимок правил и профиля фиксируется на момент подготовки. Новый формат регистрируется в activities, использует общие профили/раунды/outbox, добавляет собственные правила и миграции, не меняя старую историю.

Системные часы передаются через Clock; FrozenClock используется только в изолированных тестах и никогда не принимает время из публичного запроса. Планировщик запускается внешним cron; таймер веб-процесса не используется.

При конфликте старого продукта и технического документа последнее напоминание — вторник 21:00 МСК, по явному указанию владельца и #16. Никакого автопродления записи.
