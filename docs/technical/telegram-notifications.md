# Пользовательские уведомления Telegram

Шаблоны: `myteam/user_messages.py`. Все четыре сообщения начинаются с названия конкретной активности из Round/activity registry, без префикса МАЙТИМ и календарных дат. Служебные отчёты владельцу не меняются.

- Среда 09:00 МСК: назначение, участники с прямыми ссылками на Telegram, организатор и инструкции формата; кнопка «Открыть активность».
- Если группа не сформирована: «На этой неделе не собралось достаточно участников для активности. Попробуем в следующий раз! На следующую неделю нужно записаться отдельно». Кнопка открытия приложения.
- Вторник 09:00 МСК: «Как прошла активность? Поделись результатом — это поможет сделать следующие активности интереснее». Только без окончательного ответа; кнопка оценки.
- Четверг 09:00 МСК: «Присоединишься к активности на следующей неделе?» Только ещё не записавшимся; без текста про добровольность. Кнопки «Записаться» и «Отказаться».

Кнопки приглашения вызывают ту же `rounds.enroll`, что веб: идентичная валидация профиля/канала и закрытия записи. Получатель определяется по проверенному webhook sender, private chat и отправленному приглашению с совпадающими round/person/chat/message_id; переданный клиентом person_id не используется. TelegramUpdate подавляет повтор одного update; повтор действия не меняет ревизию. Ответ обновляет исходное сообщение, не создаёт нового сообщения. Обратное действие возможно до закрытия записи, после закрытия кнопки убираются. Ошибка изменения сообщения не откатывает сохранённую запись; повтор нажатия безопасен.

Промежуточных сообщений с контактами больше нет: старые /start c_ и /start m_ ничего не отправляют, ожидающие уведомления contacts подавляются. В опубликованной своей группе доступны прямые ссылки: https://t.me/username либо tg://user?id=… при отсутствии username. Привязка к числовому ID берётся только из проверенного Telegram-профиля; реальная доступность открытия контакта без username зависит от клиента и настроек Telegram и отдельно ещё не проверена. ID/имена чужих групп не выдаются.

Проверки используют локальный PostgreSQL и подменённый транспорт Telegram. Реальные приглашения и рассылки ради тестирования не отправляются. Схема БД не изменяется; история отправок и пользователей сохраняется.
