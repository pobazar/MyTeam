# Недельный цикл: выбор, восстановление и отмена

## Что исправлено

Прежние слабые места: постоянный fallback на Coffee; следующий раунд создавался преимущественно после успешной публикации; signup_only мог остаться в бесконечном ожидании; пропущенный prepare блокировал publish; поздний ручной publish только молча пропускался; bootstrap плана мог перезаписать уже объявленный формат или не запуститься из-за ручного изменения. Теперь эти исходы обрабатываются явно.

## Выбор формата

`ensure_round` сохраняет activity, rules_version и selection один раз под PostgreSQL-блокировкой activity_rotation. Параллельные запросы не создают два раунда и не перевыбирают формат. selection хранит источник (plan/rotation/legacy/manual), название, алгоритм, кандидатов, веса и сглаженные рейтинги на момент выбора. Изменение будущих оценок не переписывает уже объявленный выбор. План 28.10 Coffee / 04.11 Code Names сохранён.

Без явного плана выбираются только включённые полноценные адаптеры; signup_only, неизвестные версии и неполные реализации не участвуют в ротации. Сейчас готовы Random Coffee и Code Names; ранее до реализации игры был готов только Coffee. Каталог не «заканчивается»: после прохождения всех форматов выбор продолжается.

Алгоритм weighted-variety-v1: при двух и более кандидатах исключается предыдущий формат; среди оставшихся случайный взвешенный выбор. Оценки берутся только из опубликованных раундов за 26 недель, outcome=yes и rating=1..5. Среднее сглажено тремя условными оценками 3.5, чтобы одиночная оценка не перекосила выбор. Вес = сглаженный рейтинг / (1 + число появлений за последние 8 раундов). Новый или отсутствующий max(4, 2×число форматов) недель кандидат получает приоритет. Это сочетает рейтинг, разнообразие и защиту от вытеснения. При двух форматах строгое чередование неизбежно, рейтинг влияет на частоту, когда альтернатив больше двух. Это вероятностный выбор, не фиксированный цикл.

Когда нет ни одного готового формата, создаётся явное пустое состояние без возможности записи и без приглашения на несуществующую игру. Если готовый формат появляется до объявления/записи, пустое состояние заменяется реальным выбором с тем же ID. Объявленные форматы, регистрации, опубликованная история и оценки не заменяются автоматически.

## Независимый календарь

`ensure_calendar` создаёт ближайший раунд и раунд, который должен быть виден в блоке следующей активности. Он вызывается при bootstrap и событиях, до попытки подготовки/публикации. Отсутствующий следующий раунд также создаётся при первом открытии активностей; обычный путь с уже существующим раундом не добавляет SQL-запросов. Поэтому отмена, пауза или пропущенный Actions не убирают запись на следующую неделю. Переход интерфейса остаётся во вторник 21:00 МСК; публикация — в среду 09:00. Автоматической записи пользователей нет.

## Ошибки и восстановление

- Нет подготовленного состава из-за пропущенного prepare: publish безопасно готовит его в своём раунде и публикует.
- Полный валидный ручной состав без prepared_at: принимается с теми же Member, snapshot и Meeting; не перемешивается.
- Частичный/невалидный состав: не удаляется и не перестраивается поверх ручных правок. Раунд получает cancelled и причину; записям и черновику ничего не удаляется.
- Неготовая/неизвестная активность: уже объявленный формат не меняется на Coffee. В публикацию — отмена, один Telegram round_cancelled каждому активному записавшемуся и отдельный owner_cancelled владельцу. Ссылка на следующие активности, без дат и debug-текста.
- Временная ошибка БД: вложенная транзакция откатывается; повтор использует те же Round/Enrollment/выбор. Не отменяем активность при первой временной ошибке.
- Если publication так и не состоялся до среды 15:00: publish после cutoff фиксирует отмену. Резервные cron 09:30 и 15:05 явно вызывают только publish. Старые назначения и приглашения отменённого раунда не отправляются.
- Повтор отмены не создаёт новые сообщения. После окончания пользовательской недели устаревшее публичное уведомление не отправляется; факт отмены остаётся в БД.
- Ручная пауза остаётся паузой даже после cutoff. Использовать pause_round, а не изменять только boolean в обход источника паузы. Миграция помечает известную системную паузу Code Names 04.11 как placeholder; остальные существующие паузы сохраняются как ручные/legacy.
- Приглашение можно явно восстановить до закрытия записи, а не только в первые шесть часов четверга. Другие события не догоняют эту рассылку.

Если GitHub вообще не выполняет ни основной, ни резервные запуски, либо Render/БД длительно недоступны, код не может самостоятельно отправить сообщение. После восстановления выполнить workflow_dispatch publish с нужной round_date: в срок — восстановление, после срока — отмена. Тестовое время и реальные тестовые рассылки не используются.

## Данные и проверки

Миграция 0007 только добавляет selection/cancelled_at/cancellation_reason и состояние cancelled, замораживает метаданные существующих выборов. DB defaults оставлены для совместимости старых writers при rolling deploy. Профили, Enrollment, Member, Feedback и Achievement не пересоздаются. Ключи прежних уведомлений и задач сохранены.

Проверки охватывают миграцию с исходной схемы и сохранность истории/ачивок, параллельный выбор, неизменность выбора, рейтинг и разнообразие, исчерпанный/пустой каталог, поздний Actions, пропущенную подготовку, полноценный и частичный ручной состав, временную ошибку БД, повторную отмену и доставку, manual pause, неизвестный формат, независимую запись и SQL-бюджет обычного экрана. Все участники и Telegram transport в тестах изолированы.
