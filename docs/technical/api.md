# JSON API для Pages

Статический клиент получает только JSON, не разбирает и не вставляет серверный HTML. Сохраняются существующие Django-сессии, Telegram-подтверждение, CSRF и серверные проверки профиля.

- GET /bridge/bootstrap/ (только разрешённый Origin): anonymous session + csrf_token.
- POST /api/login/: явный запрос кода после публичного онбординга. Само открытие сайта код не создаёт.
- POST /api/login/status/: подтверждение/срок кода; успешный вход вращает session key и CSRF.
- POST /api/onboarding/: завершение введения для ранее авторизованного аккаунта с незавершённым онбордингом.
- GET/POST /api/profile/: три поля, ачивка, валидационные ошибки. Каждая полученная ачивка содержит key/title/description/earned_at; дата — исходный Achievement.created_at пользователя.
- GET /api/activities/: текущая и следующая недели, состав, инструкции, состояние записи и результата; next.enrollment_count — число активных записей на следующий раунд (включая пользователя, без отменённых). Значение приходит в обычном GET, без polling. После собственного enroll/cancel клиент изменяет этот снимок на±1 только при фактической смене состояния в успешном POST-ответе; дополнительный GET не выполняется.
- POST /api/rounds/<uuid>/enrollment/: action=enroll/cancel. Без автоматической записи.
- GET /api/history/: только опубликованное собственное участие и собственная оценка.
- GET/POST /api/meetings/<uuid>/feedback/: доступ только своему участнику, общая форма yes/no; для yes обязательны 1–5 звёзд, комментарий необязателен; для no причина необязательна, рейтинг очищается.
- POST /api/logout/: отзыв серверной сессии, 200 JSON без редиректа. Повтор/истёкший токен также 200; действующая сессия требует CSRF.

Запросы: Authorization: Bearer <opaque session key>, для POST также X-CSRFToken. Тело JSON. Успешные ответы и ошибки бизнес-валидации содержат csrf_token; ротация сессии передаётся X-Myteam-Session. Секреты Render/Supabase/бота никогда не передаются клиенту. UUID/пользователь из тела не удостоверяют личность.

401 — отсутствующая/истёкшая сессия; 409 со state=needs_onboarding/needs_profile — обязательный этап; 422 — fields с ошибками формы; 404 — недоступный объект. Бизнес-ошибки API не перенаправляют на HTML/Telegram-вход.

Dashboard/history read models общие с прежними серверными представлениями: правила, фильтры доступа и бюджеты SQL не дублируются. Legacy HTML-маршруты временно сохранены для старых вкладок; новый Pages-клиент их не использует. Миграций данных этот переход не требует.

Framework-ошибки 404/405/500 на /api/* также приводятся к JSON; редиректы не используются. Logout не создаёт новую анонимную сессию после удаления прежней.


Тайм-аут запросов статического клиента — 90 секунд, включая авторизацию, загрузку экранов, сохранение и завершение сессии. Это позволяет дождаться запуска бесплатного Render после простоя. При уходе с экрана запрос по-прежнему отменяется сразу. Общий footer предупреждает, что запуск сервера может занять около минуты.

## Сохранение входа между вкладками

Подтверждённая учётная запись сохраняется в `localStorage` (`myteam.account`: непрозрачный Django session key и подсказка этапа профиля). Сервер остаётся источником прав и состояния аккаунта; срок Django-сессии — 14 дней. Новая вкладка и повторное открытие того же браузера восстанавливают вход, пока сессия не истекла, не отозвана или пользователь не очистил данные сайта. Это не переносит вход между устройствами, браузерами или разными origin.

Анонимная сессия и ожидающий Telegram-код остаются в `sessionStorage`; другие вкладки не подхватывают незавершённую авторизацию. Старые подтверждённые сессии автоматически переносятся при загрузке новой версии клиента. Если localStorage недоступен, вход продолжает работать в текущей вкладке.

События `storage` синхронизируют подтверждённый вход, смену ключа/этапа, выход и очистку хранилища между открытыми вкладками. При смене аккаунта отменяются запросы и очищаются старые CSRF и экраны. Logout/401 очищают локальный вход во всех вкладках; новый вход всё равно требует подтверждения бота. Состояние мини-подсказок остаётся локальным для вкладки.

Целевая проверка: `node scripts/qa/session-browser.cjs`. Проверяет перенос существующего входа, новую вкладку, восстановление из persistent browser storage, общий logout/login, смену ключа, изоляцию неподтверждённого входа и серверный 401. Все API перехвачены; production и Telegram не вызываются, скриншоты не создаются. Миграций БД нет.
