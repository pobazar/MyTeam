# Дизайн МАЙТИМ: TUI в вебе

Источник — предоставленный владельцем архив `tui-design-system-codex.zip`, сохранённый без изменения спецификаций в [design-system](../../design-system/README.md). Присланные отдельно скриншоты уточняют AppBar: возврат слева, заголовок по центру на iOS/desktop и слева на Android, компактный заголовок при прокрутке, минимальная desktop-высота 64 px. Содержимое примеров не переносится в продукт. Дизайн-система заменяет прежнюю палитру как основной источник оформления.

## Применение

- `python scripts/generate_design_tokens.py` воспроизводит `web/tokens.css`; файл содержит семантические Day-цвета из `tokens/colors.json`, включая alpha. Например, base-alt `#F2F4F7`, accent-1 `#FFDD2D`, accent-2 `#428BF9`. Неразрешённые внешние aliases не заменяются выдуманными значениями: используются именованные resolved Day fills из каталога. Тёмная тема не включена.
- Текст: Desktop/Heading 3 — 36/40, Heading 4 — 28/32, Heading 5 — 24/28; iOS/Heading Large — 30/36; Body/L — 17/24, Body/M — 15/20, Body/S — 13/18. Локальный системный шрифт вместо загрузки отсутствующих в архиве SF Pro/Hauss; Android использует доступный Roboto. Это адаптация, а не обещание идентичной метрики шрифтов на всех ОС.
- `tui-button`: large/primary/normal, 56 px, radius 12, жёлтый primary; secondary на neutral-1. Hover/pressed используют соответствующие токены. Тексты форм, карточки, skeleton, onboarding-flow и feedback следуют общей семантике компонентов. Поля ввода не представлены отдельной полной спецификацией: применена стандартная веб-форма с label, focus и валидацией.
- `tui-rating`: quantity 0–5, пять элементов 40×40, gap 16, общая ширина 264 px. Ноль — начальное состояние, сохранение требует 1–5. Нативная radio-группа поддерживает клавиатуру, есть доступные названия и focus. Стандартный контур заменён предоставленными владельцем оригинальными SVG `web/icons/star-idle.svg` и `star-active.svg`: серый/жёлтый с исходными маской, градиентом и прозрачностью. До выбора все звёзды серые, после выбора первые N жёлтые. В истории те же SVG компактно отображаются по 24 px с промежутком 8 px (веб-адаптация read-only, не отдельный вариант из JSON).
- Иконки истории/профиля — оригинальные `doc-clock.svg` и `user-impersonal.svg` владельца. Назад/закрыть — стандартные SVG. Декоративные «М/Ы» на онбординге составлены из текста и CSS, внешних иллюстраций нет.

## Экраны и адаптация

Статический UI остаётся на Pages. Изменения не требуют API, миграций, Telegram или инфраструктурных секретов.

Активности — главный экран. Профиль и история — отдельные `main`-экраны с AppBar и возвратом, без модального слоя. Только один main виден одновременно. Под ними сохраняются загруженные активности и позиция прокрутки: возврат не делает повторный GET. Профиль/история при открытии получают свежие данные с skeleton и retry. Отмена перехода прерывает запрос; поздний ответ не возвращает пользователя назад. Браузерные назад/вперёд поддерживаются hash-маршрутами.

Оценка — native dialog поверх активностей или истории; закрывается крестиком/Escape и возвращает в источник. После сохранения обновляется источник. Управление фокусом, блокировка фоновой прокрутки, ограничение высоты и внутренняя прокрутка диалога сохранены.

Основная компоновка зависит от ширины окна. До 720 px — одна колонка, выше — широкая текущая неделя и меньший блок следующей; профиль в двух колонках. AppBar sticky: desktop 72 px (выше минимальных 64), mobile Android/универсальный 64, iOS 56. Эти высоты мобильного AppBar — веб-решение по платформенной практике, не значение из отсутствующей спецификации AppBar JSON. Длинные заголовки не перекрывают действия. Большой заголовок заменяется компактным в AppBar при прокрутке. Интерактивные области не меньше 44 px, учтены safe-area, dynamic viewport, системное масштабирование текста и reduced-motion. Нижние CTA прокручиваются вместе с формами, чтобы экранная клавиатура не перекрывала фиксированную панель.

ОС определяется по доступному user agent, включая iPadOS с desktop UA и touch. Это вспомогательное оформление; при неизвестной ОС работает универсальный вариант. UA не используется для доступа или бизнес-логики. На широком окне действует desktop-компоновка независимо от ОС. Системные часы/status bar/home indicator не рисуются.

## Проверки

74 PostgreSQL-теста приложения проходят. Дополнительно изолированный Django/SQLite прогон с тремя вымышленными участниками проверяет вход, обязательный профиль, запись/отмену, индивидуальные yes/4 и no-ответы, историю, достижение, ошибки/retry, отсутствие реальных доставок и немедленный logout с отзывом серверной сессии.

Повторяемый UI regression:

```sh
# Playwright нужен только для QA; не является runtime-зависимостью приложения.
npm install --prefix /tmp/myteam-ui-tools playwright
NODE_PATH=/tmp/myteam-ui-tools/node_modules CHROMIUM_PATH=/usr/bin/chromium \
  MYTEAM_SCREENSHOTS=/tmp/myteam-design-shots node scripts/qa/design-browser.cjs
```

Скрипт поднимает локальную статику и перехватывает все API-запросы JSON-фикстурами: production и Telegram не вызываются. Проверяет 1440, 393, 390 и 320 px, Android/iOS UA и touch, отсутствие горизонтального переполнения, отдельные экраны, browser back без повторного GET активностей, retry, сохранение профиля, запись, rating 264 px, условное поле причины, Escape, сохранение из истории, защиту от позднего ответа и logout.

Эти мобильные проверки выполняются в Chromium с эмуляцией. Физические Android/iPhone и движок Safari этой проверкой не подтверждены; отдельно требуют ручной проверки клавиатуры, safe-area и поведения браузерных панелей.

## Уточнение блоков профиля и двухшаговой оценки

Вложенная карточка достижения использует принцип tui-card-medium: иллюстрация/заголовок/описание в одном неинтерактивном контейнере внутри tui-card-large. Отдельного обязательного места logout в каталоге нет: принято обычное веб-решение — самостоятельное второстепенное действие под блоками профиля, без смешивания с достижениями и без перегрузки AppBar. Иллюстрация использует предоставленную звезду, ачивка больше не оформлена кнопкой/жёлтым бейджем. Пустое состояние общее, без обещания «Первого кофе».

У профиля отдельные skeleton-блоки полей/достижений при одном API-запросе. Все загрузчики лишены видимого текста, role/status и доступное описание сохраняются. Оценка — явные кнопки yes/no с последующим условным шагом; причины no теперь необязательны и на сервере. Подсказка не заменяет label. Для исправления выбора есть «Изменить ответ», введённый комментарий не пропадает.

Полный браузерный прогон и скриншоты остаются на финальное тестирование по просьбе владельца. Для изменённой серверной логики выполнены18 изолированных PostgreSQL-тестов API/feedback/performance: подсчёт исключает отмену и другие раунды; no без комментария сохраняется как final; бюджет запросов активностей остаётся5. Миграций нет. Визуальные размеры skeleton/карточек, мобильный флоу и фокус нужно проверить в финальном прогоне.


## Коллекция достижений по новому референсу

«Мои достижения» показывает полученные значки и реальный count. Для «Первого кофе» сгенерирован оригинальный прозрачный PNG в объёмном зелёно-золотом стиле с чашкой; иллюстрации и названия стороннего продукта из референса не копируются. В профиле — badge112px без текстовой карточки, подробности — отдельный dialog до600px: изображение176px, дата, заголовок, описание по центру; закрытие сверху справа и Escape. Этот вариант заменяет предыдущую карточку card-medium. На телефоне значки переносятся, диалог ограничен dynamic viewport и прокручивается при необходимости. Скелетон блока соответствует значку.

Изображение профиля loading=lazy, в скрытом диалоге нет src до открытия: иллюстрация не загружается на гостевом онбординге. PNG — неизменённый результат генерации, сохраняет прозрачность. Для новых типов есть временная стандартная звезда до добавления собственного арта; API пока выдаёт только фактически существующий first_coffee. Даты не выдумываются: earned_at берётся из Achievement.created_at в коррелированном подзапросе пользователя. Булев признак для legacy HTML вычисляется из наличия этой даты, без второго SQL. Профиль остаётся2 SQL.

Открытие/закрытие диалога не делает GET и сохраняет редактируемые поля профиля. При навигации/выходе диалог закрывается. Host тостов выбирает открытый dialog, поэтому результаты сохранения не окажутся под достижением. Полный браузерный прогон и скриншоты по действующему указанию владельца отложены до финального тестирования. Выполняются только целевые серверные проверки даты/приватности/бюджета и синтаксис/diff.


## Финальный desktop-прогон и новая галерея

По новому указанию владельца выполнен полный серверный прогон:76 PostgreSQL-тестов проходят. Устаревший критерий обязательной причины no в participant_flow приведён к согласованной необязательности. Браузерный scripts/qa/review-browser.cjs прошёл71 состояние на1440×1000 Chromium: онбординг/код/истечение/ошибки, обязательный профиль, все состояния текущей/следующей активности, регистрация/отмена и их ошибки, загрузка/валидация/сохранение профиля, награда/дата/черновик, пустая/смешанная/длинная история, обе ветки оценки и0–5 звёзд, readonly, тосты в dialog/после закрытия/стопка/hover/timeout, logout. Горизонтального переполнения и JS-ошибок нет. API этого browser-прогона — изолированные JSON-фикстуры, production-записей и реальных отправок Telegram нет; мобильные устройства в этот прогон не входили.

Прямая проверка через ссылки DOM подтверждает: enroll/cancel не вызывают GET активностей и не заменяют текущую карточку либо саму кнопку. При успехе синхронизируются только текст/статус/локальный count, при ошибке всё сохраняется. Native validation заменена локализованной подсказкой у поля и тостом, без английского tooltip браузера. После восстановления временной ошибки проверки Telegram-кода возвращается нормальный текст ожидания.
