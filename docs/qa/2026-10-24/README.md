## Проверенный сценарий

1. 26 октября: четыре отдельных браузерных контекста проходят онбординг, заполняют профили и добровольно записываются на Random Coffee 28 октября — 4 ноября.
2. 27 октября 21:00 МСК: запись закрыта; записанный участник видит ожидание состава.
3. 27 октября 22:00: подготовлены две пары, четыре участника. Повторный tick сохраняет UUID встреч и снимки профилей.
4. 28 октября 09:00: publication_paused блокирует публикацию; после снятия паузы публикация проходит. Сформированы четыре сообщения-встречи, транспорт доставки заменён локальной функцией. Повторный tick не создаёт дубликатов. В следующем раунде 0 записей.
5. Все четыре участника открывают свои встречи. Ответы: два «Да», один «Не получилось», один «Пока нет». Только два ответивших «Да» получают личную ачивку, ответ собеседника сам по себе ачивку не даёт.
6. 2 ноября 12:00: первый запрос обратной связи создаётся только одному участнику с неокончательным ответом.
7. 3 ноября 21:00: последнее напоминание создаётся только тому же участнику. До отправки он меняет ответ на «Да» через браузер; очередь отменяет напоминание. Всего три личных ачивки.
8. 4 ноября 09:00: раунд завершён, все четыре участия сохранены. Встреча доступна в истории. Новые раунды не содержат автоматических записей.

Время ускорялось только через тестовую реализацию Clock в отдельном процессе. Вызовы tick выполнялись напрямую; это проверка логики расписания, не подтверждение работы Render Cron. Внешний Telegram, контакты и реальная доставка не проверялись. Служебные отчёты владельцу в этом прогоне отключены. Конкурентная работа PostgreSQL проверяется отдельным существующим набором тестов, не этим SQLite-прогоном.

Критических ошибок в проверенном сценарии не обнаружено. На мобильном экране карточки идут друг под другом, горизонтальный скролл отсутствует. Скриншоты фиксируют реальный DOM приложения, без дорисовки.
