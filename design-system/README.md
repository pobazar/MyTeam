# TUI — очищенные спецификации дизайна для Codex

Это результат преобразования 13 файлов `.fig` в компактные JSON-спецификации для реализации интерфейсов.

## Куда смотреть

1. `manifest.json` — перечень файлов и охват.
2. `tokens/colors.json` — именованные цветовые стили и заливки, в том числе Day/Night.
3. `tokens/color-variables.json` — семантические переменные цветов, значения по режимам и алиасы.
4. `tokens/typography.json` — стили текста: семейство, начертание, размер, высота строки и расстояние между символами.
5. `tokens/metrics.json` — числовые и прочие переменные.
6. `tokens/effects.json` — стили эффектов.
7. `components/*.json` — компоненты, их варианты, визуальные пресеты, ограниченные примеры внутренней структуры и фрагменты авторских пояснений.

## Принципы использования

- Сначала ищи существующий семантический токен; не заменяй его произвольным HEX.
- При реализации компонента выбирай вариант по `properties` (например, platform/system, size, state, appearance), затем применяй `appearancePresets[appearance]`.
- Используй `anatomyExamples` как упрощенную структуру вложенных элементов; она **не является** полноценным описанием отрисовки или исходным кодом.
- Не выводи универсальное дизайн-правило из одного примера компонента, если оно не закреплено токенами или описанием.
- Отсутствие параметра не означает ноль/false и не дает основания его выдумывать. При расхождении реального макета и JSON приоритет — у подтвержденного макета.
- В Figma размеры указаны в px. При переносе в Android dp, iOS pt или CSS px перепроверь масштаб и правила платформы.
- Изображения, точные пути иконок, анимация и бинарная векторная геометрия намеренно отсутствуют.

## Инструкция для `AGENTS.md`

> Для любых изменений UI сначала читай `design-system/manifest.json`, затем нужные `tokens/*.json` и `components/*.json`. Используй указанные состояния и размеры. Не меняй дизайн-токены без отдельного требования, не придумывай отсутствующие параметры, обеспечивай адаптивность и доступность интерфейса. Если компонент не описан, используй ближайшую стандартную практику проекта и явно отмечай расхождение с дизайн-системой.

## Методика очистки

Повторяющиеся общие стили сведены в один каталог. В файлах компонентов сохранены только их собственные мастер-компоненты и варианты, без импортированных по ссылке тысяч чужих компонентов, метаданных редактора и служебных ID. Повторяющиеся внешние appearance-параметры вынесены в именованные пресеты.
